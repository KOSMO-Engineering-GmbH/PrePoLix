# Development

## Build and run

You need a current stable Rust toolchain (`rustup`). On Linux the build also needs the ALSA
development files for audio output (Debian/Ubuntu: `sudo apt install libasound2-dev`, Fedora:
`alsa-lib-devel`). At run time Linux needs `libxkbcommon-x11` (X11) or `libxkbcommon` (Wayland) and a
Vulkan or OpenGL driver; most desktop installations have them.

```sh
cargo run --release
```

Open a model or result file with *File > Open* (Ctrl+O), drag a `.inp` or `.frd` file into the
window, or pass it on the command line:

```sh
cargo run --release -- testdata/wuerfel_c3d10.inp
cargo run --release -- testdata/kragbalken_c3d8.frd
cargo run --release -- testdata/platte_mit_loch.step
```

Example models are in [testdata/](../testdata/), generated by `testdata/erzeugen.py`; the STEP files
come from Gmsh. The models with a step can be run directly with `ccx`.

## Gmsh

STEP, IGES and BREP files are imported and meshed with [Gmsh](https://gmsh.info/). It is not compiled
in but loaded as a library at run time; without it PrePoLix starts normally, only import and meshing
are missing. For development a script downloads the official library (Gmsh 4.15, from Gmsh's PyPI
package) into `target/gmsh`, where debug builds and tests find it:

```sh
python3 scripts/fetch_gmsh.py                        # Linux
python3 scripts/fetch_gmsh.py --platform windows     # Windows
```

To distribute PrePoLix, place `libgmsh.so.4.15` or `gmsh-4.15.dll` and `GMSH-LICENSE.txt` next to the
executable. Alternatively set the path to an existing library under *Tools > Settings > Gmsh*. On
Linux the Gmsh library also needs `libGLU` and `libXft`.

## Windows installer

The installer (`prepolix-<version>-setup.exe`, NSIS) is built on Linux: `prepolix.exe` is
cross-compiled with MinGW, plus the Gmsh DLL, the program icon and the license texts. It installs
to `C:\Program Files\prepolix`, adds a Start menu entry (desktop icon optional), optionally
associates `.plx` projects and registers for uninstall. CalculiX is not included.

```sh
sudo apt install gcc-mingw-w64-x86-64 nsis
scripts/build_windows_installer.sh     # -> target/windows-installer/
```

A tag `v*` builds the installer and the user guide PDF with the *Release* workflow and attaches both
to the GitHub release; *Run workflow* produces them as artifacts. PrePoLix may not write to
`C:\Program Files` without administrator rights, so the CalculiX work directory then lives in
`%TEMP%\prepolix`.

## User guide

The guide (English, Typst) is in [user-guide/](user-guide/). Build it with
`typst compile --root . --ignore-system-fonts docs/user-guide/main.typ`. New features are documented
there in the same PR, see [user-guide/README.md](user-guide/README.md).

## Crates

| Crate | Content |
|---|---|
| `plx-core` | units, formulas, selection recipes, shared types |
| `plx-mesh` | FE mesh: nodes, elements, sets, surfaces, geometry topology |
| `plx-model` | FE model: materials, sections, steps, boundary conditions, loads, commands |
| `plx-io` | file formats: CalculiX `.inp`/`.frd`/`.dat` and others |
| `plx-results` | result data model and derived quantities |
| `plx-mesher` | geometry import and meshing with Gmsh (loaded at run time) |
| `plx-job` | starting and monitoring CalculiX |
| `plx-render` | wgpu renderer and camera |
| `plx-app` | user interface (egui), the `prepolix` executable |

The lower crates know nothing about the UI and can be tested on their own (`cargo test`).
The plan and architecture notes are in [PLANUNG_TECH_STACK.md](PLANUNG_TECH_STACK.md).
